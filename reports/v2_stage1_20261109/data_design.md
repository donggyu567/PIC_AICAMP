# 확대 데이터 설계 v1

목표는 **합성·신규 TRAIN 풀 80대화 / 새 독립 VALIDATION 32대화 / 봉인 TEST 40대화**다. TRAIN 80은 복구 v1 68대화를 포함한 총합이 아니라, 기존 LLM TRAIN 24개를 유지하고 신규 56개를 더하는 풀이다. 실제 C 입력은 권한·검수를 통과한 기존 v1 TRAIN과 이 풀의 승인 부분만 합친다. A/B는 동일한 적격 v1 TRAIN만 사용한다.

|자료|생성·확보 후보|최종 적격 확인|목표까지 생성 부족|완료까지 필요한 결정|
|---|---:|---:|---:|---|
|신규 TRAIN 풀|24대화·208발화|0대화|56대화|기존24 포함 전체80 검수·사용 승인|
|독립 인간 중심 VALIDATION|0|0|32대화|신규 독립 작성·검수·gold 동결|
|봉인 TEST|0|0|40대화|독립 작성·gold 확정·담당자 봉인|
|기존 LLM VALIDATION(보조)|24대화·192발화|0|독립32에 산입하지 않음|기존 검수 후 보조 진단만|

기존24개의 생성 방법을 인간 작성으로 바꾸지 않는다. 136발화의 1인 검수, 72발화 신규 미검수, 보조192발화 미검수를 그대로 보존한다. 생성 수량과 학습 승인 수량을 별도로 관리한다.

## 유형별 확보량과 부족분

단위는 **현재 발화 라벨의 양성 발화 수**이며 대화 수와 구분한다. v1 열은 권한 미확정 후보 통계이며 신규 풀 목표에 합산하지 않는다. 원본 추진안의 “유형별 추가 양성 목표”는 제공되지 않아 그 목표 대비 부족분은 전 유형 **확인 불가**다. 원본이 확보되면 `max(0,원본이 정의한 목표-동일 범위의 실제 확보량)`으로 별도 계산한다. 원본 목표가 기존 v1 대비 추가 수량인지, 신규 풀 누적인지 먼저 확인해야 한다.

|유형(기존 순서)|v1 후보|신규 TRAIN24 후보|그중 최종 승인|이번 설계의 풀80 양성 목표 제안|현재 후보 대비 부족|원본 목표 대비 부족|
|---|---:|---:|---:|---:|---:|---|
|institution_impersonation|176|14|0|30|16|확인 불가|
|money_transfer|90|7|0|36|29|확인 불가|
|personal_information|32|9|0|36|27|확인 불가|
|app_installation|6|7|0|40|33|확인 불가|
|secrecy|21|6|0|32|26|확인 불가|
|threat_pressure|81|4|0|28|24|확인 불가|
|loan_fraud|65|6|0|24|18|확인 불가|
|information_probing|100|6|0|28|22|확인 불가|

새 목표는 희소 6유형 보강을 위한 용량 계획 제안이며 추진안 원문 수치나 이미 승인된 quota가 아니다. 후보 양성 합계59→254, 추가195를 지향한다. 승인 양성은 현재 모두0이므로 승인 기준 부족량은 목표 전체다. 무리한 라벨 추가·유사 대화 반복으로 수치를 맞추지 않는다. 사람이 실제 작성한 내용에서 타당한 양성만 세고, 목표 미달이면 수량 또는 설계의 새 버전을 결정한다.

## 56대화의 네 차수

각 차수는 위험 전개9+완전 정상 hard negative5=14대화다. 기존 위험14+정상10에 신규 위험36+정상20을 더해 위험50/정상30의 풀80을 지향한다. “위험 대화” 안의 정상 발화도 현재 발화에 위험 행위가 없으면 정상이다. 대화 길이는 내용에 맞추되 대략8~14발화를 계획한다. 발화 수는 완료 여부를 조작하는 quota로 사용하지 않는다.

|차수/단계|app|secrecy|personal|money|threat|probing|정상|합계|
|---|---:|---:|---:|---:|---:|---:|---:|---:|
|1차/3단계|2|2|1|2|1|1|5|14|
|2차/4단계|2|1|2|1|2|1|5|14|
|3차/5단계|2|2|1|2|1|1|5|14|
|4차/6단계|2|1|2|1|1|2|5|14|
|추가 합계|8|6|6|6|5|5|20|56|

각 숫자는 **주 위험 유형별 대화 설계 슬롯**이며 양성 발화 수와 다르다. 기관 사칭·대출 사기는 적절한 독립 가족에 포함하되 모든 대화에 사칭·다중라벨을 넣지 않는다. 각 발화에 위험 행위 근거를 요구하고, 3종 이상 멀티라벨은 자동 탈락 대신 독립 검수의 우선 점검 대상으로 둔다.

|유형|새 가족 설계 방향(본문 아님)|짝지을 정상 hard negative|
|---|---|---|
|app_installation|업무도구 위장 배포, 문서열람 플러그인, 가짜 배송보안 업데이트 등 서로 다른 유입·요구 단계|공식 스토어/공식 채널에서 사용자가 요청한 설치 안내, 설치 거절을 수용하는 지원|
|secrecy|주변 확인 차단, 금융기관 문의 차단, 허위 내부조사 비공개 요구 등 다른 관계·시간 전개|다른 고객 정보 보호, 정당한 비밀유지 안내와 외부 진위 확인 허용|
|personal_information|계정 회수 위장, 허위 자격검증, 정산서류 위장 등 다른 민감정보 요구 목적|거래에 필요한 최소 정보, 민감정보를 받지 않는 공식 상담|
|money_transfer|납품 정산 변경, 거짓 예약보증, 환급 수수료 등 다른 대금 흐름|실제 주문 대금 확인, 취소·환불을 허용하는 정상 결제|
|threat_pressure|법적 제재 위협, 서비스 중단 위협, 가족 피해 압박 등 다른 권력·관계 구조|권리·기한의 사실 안내, 검증·거절 기회를 주는 정상 상담|
|information_probing|연락 가능 시간, 동거 여부, 자금·기기 이용 환경 떠보기 등 수집 목적이 다른 전개|배송 시간 조율, 동의 기반 서비스 요구 파악|

위 방향도 기존 모든 scenario registry와 의미적으로 대조한 후에만 가족을 할당한다. 단순 ID 분리는 독립성 증거가 아니다. TEST의 가족별 상황은 이 개발 문서에서 작성하지 않고 독립 평가 담당자가 관리한다.

## 제작 방법·출처·권한

각14개는 실제 인간 직접 작성7 / LLM 초안+사람 검수4 / 허가된 원문 증강3을 계획한다. 추가56개 기준28/16/12이며, 원문 증강 허가가 없으면 해당12개를 **실제 인간 직접 작성**으로 대체해40/16/0으로 한다. Codex는 인간 작성 슬롯의 본문을 대신 만들거나 인간 작성이라고 표시하지 않는다. 기존24개는 `llm_simulation` 그대로 보존한다.

향후 manifest에는 conversation_id, split, family_id, source/source_item, author_id, generation_method, LLM model/prompt version(해당 시), rights_holder, permission_scope/evidence, 원문 해시(제한 저장), masking QA, 현재 발화 label rationale, 각 검수자·시간·의견, final agreement, training-use decision과 데이터 지문을 기록한다. 미마스킹 원문은 Git에 넣지 않는다. 권한이 불분명한 기존 v1도 적격으로 자동 포함하지 않는다. 작성자·권리자·지정 검수자의 실제 결정이 필요하다.

## 독립 VALIDATION32 / TEST40

독립 VALIDATION은 실제 인간 작성·검수 중심으로 새32개(위험20/정상12 제안)를 확보한다. 8유형 모두 양성/음성을 포함하고, 임계값 개별 선택에는 유형별 양성10·음성10발화 및 양성 대화3개 이상을 요구한다. 불충족 유형은0.5 유지와 지원 수 부족을 기록한다. 대화 수32개만으로 이를 달성했다고 간주하지 않는다. TRAIN 작성자는 가능한 한 VALIDATION 작성에서 제외한다.

TEST는 독립 평가 담당자가 새40개(위험24/정상16 제안)를 별도 확보한다. 모든 유형에 최소 양성10발화·3개 독립 가족과 충분한 음성/정상 상담을 확보하는 coverage 목표를 제안하되, 미달 시 주장을 제한하고 N/A를 보고한다. TRAIN/VALIDATION의 작성자·출처·원문 파생·의미적 가족이 겹치지 않도록 하고, 사람 작성과 독립 검수 중심으로 생성 방법 편향도 줄인다. 이 수량은 현장 성능 보장이나 통계적 충분성 증명이 아니다.

TEST 담당자는 모델 선택 전에 gold와 membership·hash·보관자·접근정책을 봉인한다. 개발 저장소에는 본문·정답 대신 메타데이터 영수증만 둔다. 개발자는 학습·threshold·epoch·seed 선택에 TEST를 읽지 않는다. 최종 선택이 동결된 뒤 평가 담당자가 등록된 arm/seed 전체를 한 최종 작업으로 평가한다. 이번 단계는 TEST 본문 생성·gold 제작·추론을 하지 않는다.

모든 신규 데이터는 가족·출처/파생·작성자 연결 그룹을 먼저 예약하고 대화 전체와 그 문맥을 한 역할에 둔다. 완전/정규화 중복·0.80 유사 후보와 전체 대화 전개를 검사하고 사람이 의미적 가족을 확인한다. 공통 짧은 정상 응답도 이번에는 자동 예외 승인하지 않는다. 미해결 충돌은 사용 차단, 이력 보존, 가족 재할당 후 버전 증가로 처리한다.

## v1 분할 전략의 선택

|정책|장점|문제·누출 위험|이번 채택 여부|
|---|---|---|---|
|적격 기존 v1 전체를 TRAIN 유지 + 신규 독립32/40|작은 기존 자료를 학습에 보존; 과거 모델과도 독립인 신규 평가를 설계 가능; 희소 유형 가족을 신규 확보|권한·라벨·출처 적격성 검증 필요; 신규 작성 편향과 비용; 인간 작성 평가도 실통화 일반화를 보장하지 않음|**확대 프로토콜의 단일 채택안**|
|v1 48/10/10 후보|기존 데이터로 비교를 빨리 준비; 고정 그룹 manifest 존재|128개 짧은 정상 응답 예외 미승인, holdout517발화 미검수, TEST 앱설치/비밀유지 양성0, 위협1·개인정보2; 과거 v1은68개 모두 학습해 독립 TEST가 아님|원본 보존, 과거 진단 후보에 한정|

새 전략의 적격 TRAIN이 확정되면 과거 후보의 validation/test도 **독립 신규 holdout으로 사용하지 않고**, 권한·검수 통과 시 기존 학습 자료의 일부로만 다룬다. 신규32/40에 과거 후보20개나 LLM24개를 덧붙이지 않는다. 신규 평가와 학습 간 의미적 충돌이 발견되면 평가 담당자가 독립성 회복을 결정하고 전 arm의 입력과 protocol을 함께 재동결한다. 두 전략의 성능 숫자를 같은 benchmark처럼 혼합하지 않는다.
