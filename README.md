# PIC: 실시간 보이스피싱 위험 분석·경고

## 현재 프로젝트 방향

PIC는 개인 휴대폰 통화 상황에서 보이스피싱 위험을 분석하고 앱에 결과를 보여 주는 시연 프로젝트다. **시연 앱의 음성 입력은 마이크**다. 휴대폰의 실제 통화 음성을 앱이 직접 가져오는 기능이나 통신사 제휴가 완료되었다고 가정하지 않는다.

2026-10-23에 정한 방향은 인식 성능이 낮았던 기기 내 ONNX STT를 **ElevenLabs 실시간 STT API**로 교체하는 것이다. 음성은 앱에서 자체 서버를 거쳐 ElevenLabs로 보내고, 인식된 텍스트는 앱으로 돌려받아 **기기에서 개인정보를 마스킹**한다. 마스킹된 텍스트를 서버의 후속 분석 입력으로 보낸다.

이 방향은 이전 [3차 멘토링 후 논의 문서](https://docs.google.com/document/d/1QjDP5g1heAxdiuELIFnRhXsd6y3vRl9sP4rQXAZ9pos/edit?tab=t.0#heading=h.nq14f2gpb8qd)의 STT 후보 검토와 통화 음성 연동 가정보다 최신 결정이다. 이후 작업은 아래 흐름을 기준으로 한다.

## 목표 파이프라인

```text
앱: 마이크 음성 수집
  → 서버: 음성을 ElevenLabs 실시간 STT API에 전달
  → 서버: 인식된 텍스트를 앱에 반환
  → 앱: 개인정보 마스킹
  → 앱: 마스킹된 텍스트를 서버에 전송
  → 서버: OpenAI API를 이용한 LLM 발화 보정
  → 서버: 기존 위험 탐지 AI 모듈 분석 및 위험도 계산
  → 서버: OpenAI API를 이용한 LLM 통화 문맥 위험도 판단
  → 서버: 분석 결과·경고/근거 생성 후 앱에 반환
  → 앱: 결과 화면 출력
```

STT에 보내는 **음성은 마스킹 전에 기기 밖으로 나간다.** ElevenLabs가 인식한 원문 텍스트도 앱에 돌아온 뒤 마스킹된다. 따라서 “음성과 STT가 모두 온디바이스에서 처리된다”거나 “마스킹 전 정보는 외부로 전송되지 않는다”고 설명하지 않는다. 기기 내에서 수행하는 단계는 목표 흐름의 **텍스트 마스킹**이다. 음성·원문 텍스트의 전송, 보관, 삭제 및 동의 방식은 구현과 시연 설명에서 명확히 정해야 한다.

## 서버 운영 목표

심사위원이 직접 사용할 수 있도록 서버를 상시 운영할 계획이다. 배포 환경은 **AWS Lightsail 2(임시)**를 사용할 예정이다. 이는 현재 배포 완료 상태나 최종 인스턴스 사양을 뜻하지 않는다. 외부 접근, API 키 관리, 가용성 및 실제 시연 동작은 배포 후 검증해야 한다.

## 현재 구현과 목표의 차이

- 현재 로컬 Android 앱은 마이크 입력을 기기 내 sherpa-onnx 모델로 STT 처리하고 발화 원문을 앱 전용 저장소에 기록한다. **ElevenLabs 경유 STT와 앱의 최종 결과 화면 연결은 아직 구현되지 않았다.** 다른 Android 작업 브랜치의 마스킹 코드는 현재 로컬 백엔드 작업과 통합 여부를 확인해야 한다.
- 현재 서버는 마스킹된 발화를 받아 LLM으로 보정하고, 위험 탐지 AI 결과를 바탕으로 누적 점수·경고·근거를 계산·저장하는 API를 갖고 있다. 서버의 현재 동작과 API 계약은 [서버 README](backend/document/README.md)를 따른다.
- **ElevenLabs STT 중계**, **AI 계산 이후의 별도 LLM 문맥 위험도 판단**, **상시 운영 배포**는 이번 목표 흐름에 새로 필요한 작업이다. 기존 코드가 이미 이 단계를 제공한다고 설명하지 않는다.
- 개발용 AI 모델의 판단층은 학습되지 않았다. 개발 모드 점수와 경고를 실제 탐지 성능의 증거로 제시하지 않는다.

## 다른 채팅과 작업의 기준

기획, 앱·서버 구현, 테스트, 발표 자료는 위 **마이크 → 서버 경유 ElevenLabs STT → 앱 내 마스킹 → 서버 LLM 보정 → AI 계산 → OpenAI LLM 문맥 위험 판단 → 앱 결과 화면** 순서를 따른다. 이전 ONNX STT 경로, 은행 창구 시나리오, 통화 음성 직접 연동 가정을 현재 목표로 이어 쓰지 않는다. 목표 아키텍처와 이미 동작하는 코드를 구분하고, 세부 서버 동작은 [서버 문서](backend/document/README.md)와 코드를 확인한다.
