## 앱 화면 구상

1. 최초 안내와 데이터 전송 동의: 전송 범위, 기기 내 마스킹, 자체 서버와 외부 서비스의 보관 정책 차이를 안내한다.
2. 마이크 권한 안내: Android 시스템 권한 요청에 연결한다. 거부하면 수집·전송하지 않는다.
3. 홈: 새 분석 시작, 데이터 안내 진입. 사용자 의견에 따라 기능 연결 후 별도 디자인 개선 예정. 설명·카드 수를 줄이고 시작 행동 중심으로 재구성한다.
4. 분석 진행: 연결/STT/마스킹/분석 상태, 마지막 성공 위험도, 경고·근거, 마스킹 발화를 한 화면에서 표시한다. 하단 마이크 상태와 종료 버튼은 고정한다.
5. 실시간 분석 상세: 같은 활성 세션의 경고·근거·마스킹 발화를 상세 확인한다. 상세를 열거나 돌아가도 새 세션을 만들지 않는다.
6. 최종 분석 결과: 마지막 처리까지 반영된 점수·단계·주요 경고·근거·대응 안내를 요약하고 새 분석 시작을 제공한다.
7. 데이터 안내·동의 철회: 수집 중단, 서버 기록 삭제 대기, 삭제 완료와 재동의를 처리한다.

기능명세서 4.1~4.2를 따라 STT 처리·STT 오류·서버 분석 파이프라인은 독립 화면으로 구현하지 않는다. 피그마의 해당 프레임은 참고 자료로 두고 분석 진행 화면의 상태 영역과 오류 안내로 통합한다. 기존 피그마 자체는 이번 계획 작업에서 수정하지 않는다.

실시간 상세와 최종 결과는 위험도·경고·근거 표시 요소를 공유하되, 전자는 계속 갱신되는 활성 세션이고 후자는 종료한 세션의 확정 결과다. 서버가 확인해 준 새 결과가 없을 때 점수나 위험 단계를 임의로 바꾸지 않는다.

| 2. 피그마 UI와 상태 표현 | 공통 버튼·카드·위험도·경고·발화 목록, 화면 이동, 로딩·빈 결과·실패·종료 마무리·삭제 대기. 개발용 가짜 응답으로 확인. | 안내→홈→분석 진행↔실시간 상세→종료 마무리→최종 결과 흐름과 오류 상태 확인. 가짜 데이터는 개발용으로만 사용. |
| 3. 동의·권한·세션 관리 | 동의 상태 영속화, 마이크 권한 요청, 분석 상태 관리, 현재 세션/발화 구분, 새 분석 초기화, 화면 이동 중 동일 상태 유지. | 동의·권한 없이는 수집하지 않음. 새 분석에 이전 결과가 섞이지 않음. 철회 후 재시작에도 동의 필요. 종료는 연결 준비·처리 중에도 수집을 중단할 수 있음. |
| 4. 마이크·서버 경유 ElevenLabs STT 선연결 | AndroidPcmAudioRecorder의 수집·중지 구조를 재사용하고 16kHz 모노 PCM16으로 WS /api/v1/stt 연결. ready 이후 수집·전송, 서버 세션/발화 ID 관리, 최대 10분. | 허용된 실제 API·기기에서 송신→확정 결과 수신→마지막 결과 후 STT 종료와 주요 실패 시 중단 확인. 마스킹 연결 전에는 원문을 메모리에서 일시 수신 후 폐기하고 수신 상태·개수만 확인. UI·파일·로그·후속 분석으로 원문을 내보내지 않음. |

| 6. 서버 위험 분석과 결과 연결 | 마스킹된 발화를 순서대로 HTTP 분석 API에 전송하고 응답 점수·경고·근거 표시. 보정 fallback, AI 오류와 재시도 처리. 문맥 판단은 서버 연결 완료 후 추가. | 원문 없는 요청과 masking_status=succeeded 확인. 응답 수신 때만 점수 갱신. AI 실패의 null 점수를 0으로 바꾸지 않음. 중복·순서 충돌·응답 유실을 무조건 재전송으로 처리하지 않음. |
| 7. 종료·철회·삭제 통합 | 일반 종료는 마이크부터 끄고 마지막 STT·마스킹·분석까지 반영. 실패 시 마지막 성공 결과와 미완료 표시. 철회는 즉시 수집·전송 중단, 로컬 삭제, 서버 삭제 요청, 늦은 결과 폐기. | 서버의 전체 종료·철회·삭제 계약이 준비된 후 정상 종료, 종료 중 실패, 철회 중 네트워크 실패, 삭제 재시도, 새 분석 분리를 확인. 서버 확인 전에 삭제 완료로 표시하지 않음. |
| 8. 실기기·배포 서버 검증 | 배포 주소와 WSS/HTTPS 설정, 실제 모델·외부 API·앱 종단 연결. 작은 화면·긴 발화·글자 크기·뒤로가기 등 직접 영향 경로 확인. | 실제 기기에서 시작→분석→상세→종료→최종 결과→새 분석 및 철회 흐름 확인. 무한 로딩과 중복 시작 방지. 미검증 외부 기능은 완료로 보고하지 않음. |

로딩은 화면 이동이 아니라 실제 처리 상태에 연결한다. 연결·마스킹·마지막 분석·삭제 요청에 맞는 표시를 제공하고, 실패/시간 초과에서는 진행 표시를 끝내 오류와 가능한 다음 행동을 보여 준다. 분석 종료와 철회는 진행 중 요청 때문에 막히지 않게 한다.

## 재사용할 부분과 새로 구현할 부분

- 재사용: android_legacy/app/src/main/java/com/example/pic_ai_app/audio/AndroidPcmAudioRecorder.kt의 마이크 수집·중지 구조. 현재 FloatArray 콜백을 서버 PCM16 계약에 맞추는 부분은 변경한다.
- 재사용: 기존 MainActivity의 권한 요청 패턴. 동의 조건과 수집 시작 순서는 새 상태 관리에 연결한다.
- 재사용: masking/TranscriptMasker.kt, MaskingPipeline.kt와 NER·Regex·Rule·Resolver·Renderer 및 관련 테스트.
- 검토 후 필요한 부분 재사용: MaskedTranscript, 마스킹 텍스트 저장·직렬화. 새 API의 masking_status 필드와 현재 세션 ID 규칙을 반영해야 한다.
- 새 구현/변경: Compose 화면·테마·이동, 분석 세션 상태 관리, 동의 저장, WebSocket STT 클라이언트, 분석 응답 파싱, 종료·철회 연결.
- 기존 HttpMaskedTranscriptSender는 응답 본문을 버리고 Unit을 반환한다. 새 앱에서는 위험 분석 응답을 읽어야 하므로 그대로 연결 완료 처리하지 않는다.
- 기존 기기 내 Sherpa STT, STT 모델 초기화와 원문 저장 경로는 새 파이프라인에 가져오지 않는다.

## 확인된 선행 조건과 계약 차이

1. 마스킹 계약:
   - 명세·서버 허용 토큰은 [PERSON], [PHONE_NUMBER], [RRN], [ACCOUNT_NUMBER], [ADDRESS], [OTP].
   - 기존 Renderer는 추가로 [CARD_NUMBER], [BIRTH], [EMAIL], [PW], [MASKED]를 출력하며 MaskType에는 OTP가 없다.
   - 기존 검출을 끄거나 미지원 토큰을 원문으로 되돌리지 않는다. 마스킹 이식 단계에서 필요한 서버 계약·보호 토큰 정책을 먼저 맞추고 관련 검증을 통과한 뒤 실제 전송한다.
2. 모델·런타임:
   - 현재 새 작업 폴더의 NER model.onnx는 133바이트, ONNX Runtime AAR은 132바이트로 실제 실행 자산이 아닌 LFS 포인터 상태다.
   - 실제 자산과 NER 런타임 호환성을 준비·확인해야 마스킹 전체 실행을 검증할 수 있다. 이 준비는 사용자에게 비텍스트 파일 취급 범위를 확인한 후 수행한다.
3. 현재 서버:
   - 2026-10-29 확인 시 STT WebSocket과 마스킹 발화 분석·AI 재시도 HTTP API가 있다.
   - 실제 ElevenLabs·모델·Android 연결은 미검증이고 서버 기본 AI 모드는 disabled다.
   - 별도 LLM 문맥 판단은 계약·파서만 있으며 실제 호출·저장·응답에는 아직 연결하지 않았다.
   - 전체 세션 종료·철회·삭제 API는 아직 없다. 처리 단계별 진행 이벤트도 앱에서 추측해 표시하지 않는다.
   - 응답 유실 후 처리 여부를 확인할 조회 API는 후속 과제다. 처리 여부가 모호한 발화는 무조건 새 번호로 진행하거나 재전송하지 않는다.
4. 범위:
   - 회원가입·로그인·장기 분석 이력·전화 자동 차단·실제 통화 음성 직접 수집은 현재 구현 범위에 넣지 않는다.
   - 앱 코드 작업은 새 작업 폴더에서만 수행한다. 별도 서버 작업 폴더의 코드는 이 앱 계획 작업에서 수정하지 않는다.

## 검증과 진행 관리

- 각 단계에서 구현한 정상 흐름과 발생 가능한 주요 실패 경로를 확인한다.
- 재사용 마스킹은 기존 관련 테스트를 우선 실행한다. 서버 대체 응답 검증과 실제 외부 API·실기기 검증을 구분해 기록한다.
- 서버가 아직 없는 기능은 가짜 응답으로 화면·상태만 확인하며 실제 연결 완료로 표시하지 않는다.
- 단계별 구현·검증·남은 제한과 다음 작업을 android/README.md에 갱신한다.
- 현재 다음 작업은 사용자의 2026-10-29 요청에 따라 4단계 앱 마이크·서버 경유 ElevenLabs STT 선연결이다. 마스킹 이식은 5단계로 이동한다. 실제 STT 수신을 확인하되 원문은 화면·파일·로그·후속 분석에 내보내지 않는다.
- 3단계에서 동의 상태만 DataStore에 저장하고 실제 OS 권한 요청·설정 복귀 확인·ViewModel 상태 유지를 구현했다. 분석/삭제 응답은 계속 DEBUG 모의 흐름이다.
- 저장 실패 시 새 분석 차단과 재시도, 철회 즉시 결과 삭제·늦은 응답 무시, 권한 회수 시 마지막 성공 결과를 남긴 미완료 처리를 추가했다.
- 프로세스 재시작은 동의 상태만 읽으며 진행 중 세션/결과/권한을 복원하지 않는다. 서버 conversation_id/utterance_id·실제 수집·삭제 API는 다음 연결 단계에서 다룬다.
- 기존 상태 전환 9개와 새 동의·권한·재시작·오류 테스트 11개가 통과했다. 새 테스트는 대체 저장소와 권한 검사 함수를 사용한다. 실제 DataStore 파일·OS 권한 창·기기 회전은 직접 확인하지 않았다.
- 최신 APK는 2.0.2 하나만 유지한다. 상세 빌드·Lint 결과는 README에 기록한다.
- 홈 화면 디자인 개선은 후속 작업으로 남긴다. 기능·동의·권한 흐름을 유지하면서 첫 화면의 정보량과 시작 버튼 배치를 다시 정리한다.
