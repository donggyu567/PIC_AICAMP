# AI 위험도와 LLM 문맥 판단 결합 기준

작성: 2026-11-13. 현재 시연을 위한 기준이며, 탐지 성능 검증을 거친 확정 정책은 아니다.

## 처리 흐름

마스킹된 발화와 기존 문맥을 LLM에 전달해 현재 문장을 보정하고 의심 문맥·이유·근거 발화 ID를 받는다. 서버는 보정 문장을 위험 탐지 AI에 전달하고 최근 20개 발화의 누적 위험도를 계산한다. AI 결과와 LLM 판단은 함께 저장·반환한다. LLM은 AI 점수를 받지 않으며 AI를 직접 호출하지 않는다.

## 표시와 경고

반올림 전 AI 누적 점수 0~50 미만은 정상, 50 이상 70 미만은 주의, 70 이상은 위험이다. AI 분석 실패는 판단 불가다. 정상은 안전을 보증하지 않는다. LLM 판단은 `context_attention`으로 별도 표시하며 AI 점수나 기존 경고 이벤트를 변경하지 않는다.

| AI 판단 | LLM 판단 | 표시 방향 |
| --- | --- | --- |
| 주의 또는 위험 | 의심 | AI 단계와 경고를 유지하고 LLM의 문맥 이유와 근거를 추가한다. |
| 주의 또는 위험 | 뚜렷한 의심 없음·문맥 부족·실패 | AI 단계와 경고를 유지한다. 문맥 부족과 실패는 정상 판단으로 취급하지 않는다. |
| 정상 | 의심 | AI 단계는 정상으로 유지하면서 별도 문맥 주의와 이유·근거를 표시한다. |
| 정상 | 뚜렷한 의심 없음 | AI 단계를 표시한다. 안전을 보장하지 않는다. |

LLM의 `suspicious`는 `context_attention=true`, `no_clear_risk`는 `false`, 문맥 부족·미실행·실패는 `null`이다. 경고 이벤트의 발생 조건과 화면의 주의 단계는 별개다.

## 실패 처리

- LLM 실패 시 검증된 마스킹 입력으로 AI 분석을 계속하고 `fallback`과 문맥 오류 상태를 반환한다. 기존 AI 경고는 유지한다.
- AI 실패 시 서버는 점수를 null, 표시 단계를 `unknown`으로 반환하고 LLM 결과를 별도로 보존한다. Android는 해당 실패 응답의 LLM 의심 이유·근거를 표시하고 재시도를 대기한다. 이전 성공 결과는 별도로 보존하며 재시도 성공 시 현재 분석 결과로 갱신한다.
- 양쪽 실패를 정상으로 표시하지 않는다. 마스킹 실패는 후속 전송을 차단한다.

## Android 연결 및 남은 확인

기존 분석 화면은 AI 단계·경고와 LLM 의심 이유를 표시한다. LLM의 근거 발화 ID를 읽어 앱에 남아 있는 해당 마스킹 발화를 표시한다. 발화가 없으면 생략한다. 관련 Android 테스트와 디버그 빌드가 통과했으며 실기기 검증과 최신 UIUX 화면 통합은 남았다.

정상·피싱 및 두 판단이 다른 대화로 안내 내용, 근거의 적절성, 미탐·오탐과 지연을 검증해야 한다. 점수 경계 조정, LLM에 의한 추가 경고 이벤트, 별도 위험도 결합 모델은 결정되지 않았다. 통화 종료 후 제목·요약·저장 기능은 별도 작업이다.
