# 통화 요약과 휴대폰 기록 기능 명세

## 합의한 사용 흐름

1. 통화 종료 시 처리 중인 마지막 발화까지 분석하고 최종 결과를 표시한다.
2. LLM이 마스킹된 발화로 제목·요약·핵심 위험 발화 ID와 이유·대처 안내를 생성한다. 실패하면 재시도하거나 요약 없이 저장할 수 있다.
3. 누적 위험도가 주의(50 이상 70 미만) 또는 위험(70 이상)이면 사용자에게 기록 저장 여부를 묻는다. 단계는 성능 검증 전 시연 기준이다.
4. 저장하면 제목·요약·위험 점수와 단계·핵심 발화 ID와 이유·대처 안내·마스킹된 전체 대화·시각을 휴대폰에 저장한다. 로컬 저장 성공 이후 서버의 해당 통화 기록 삭제를 요청한다.
5. 저장하지 않으면 서버 기록 삭제를 요청한다. 정상 통화는 저장을 제안하지 않으며 최종 결과 화면을 나갈 때 서버 기록을 삭제한다.
6. 기록은 사용자가 직접 삭제할 때까지 해당 휴대폰에만 보관한다. 앱 삭제나 기기 변경 시 유실될 수 있다.

삭제는 완료 응답을 확인하고, 실패·앱 종료 등으로 미완료인 요청은 상태를 보존해 재시도한다. 데이터 삭제가 완료됐다고 잘못 표시하거나 로컬 저장 실패 후 서버 원본을 삭제하지 않는다. 이는 우리 앱·서버 기록의 처리이며 외부 API 제공자의 별도 보관 정책을 의미하지 않는다. 불완전 분석은 정상으로 분류하지 않는다.

## 구현 상태

- 서버의 인증된 `POST /api/v1/conversations/summary`는 종료된 통화의 마스킹·보정 발화로 요약을 생성하고, 근거 발화 번호를 검증한다. 성공 시 `title`, `summary`, `key_utterances`(`utterance_id`, `reason`), `advice`를 반환한다. 서버는 요약을 저장하지 않는다.
- 요약 실패는 503으로 구분한다. 종료 전 요청과 철회된 통화는 409다. 응답에는 캐시 금지 헤더를 설정한다. 실제 OpenAI 품질 및 Android 연동은 확인하지 않았다.
- 기존 Android 작업 폴더에 휴대폰 기록 저장·목록·상세·삭제와 주의·위험 통화 저장 선택을 연결했다. 요약 실패 시 재시도 또는 요약 없이 저장할 수 있다. 저장 및 저장 안 함 선택 후와 정상 통화 종료 화면을 나갈 때 서버 삭제를 대기 목록에 기록하고 요청한다. 로컬 저장과 해당 삭제 대기 목록 기록은 하나의 저장 작업으로 처리한다.
- 관련 Android 클라이언트·기록 저장소·세션 테스트와 디버그 빌드는 통과했다. 실제 LLM, AWS, 휴대폰 전체 흐름과 새 UIUX 통합은 미검증이다. 사용자가 선택하기 전에 앱이 종료되면 종료 화면을 자동 복원하지 못한다. 삭제 대기 목록에 이미 기록된 요청만 앱 재실행 시 재시도한다.
- 이 문서와 로컬 구현은 AWS에 배포되지 않았다.
