# KoELECTRA v2 파일럿 사람 최종 검수

`human_review.csv`에는 정본의 16대화·136발화가 모두 들어 있습니다. 한 행은 한 발화이며 `발화_ID`는 `SYN2-TRAIN-0005-7`처럼 대화 ID와 발화 번호를 결합합니다. 최초 상태는 두 검수자 및 최종 합의 모두 **미승인**, 학습 반영은 **미반영**입니다.

## 검수 순서

1. Excel에서 UTF-8 CSV로 열고 첫 행 필터와 헤더 고정을 설정합니다. CSV에는 서식·드롭다운·자동 계산이 저장되지 않습니다. 내용을 저장할 때 **CSV UTF-8**을 선택합니다. 열을 정렬할 때는 표 전체를 함께 정렬합니다.
2. 김해린·임정윤이 136발화 모두를 독립 검수합니다. 각자 자신의 `검수_결과_이름`, `수정_의견_이름`, `검수_일시_이름`만 작성합니다. 동시에 같은 로컬 파일에 저장하지 말고 순차 작성하거나 각자 사본을 만든 뒤 `발화_ID` 기준으로 본인 입력 열만 병합합니다.
3. `검토_필요=예`인 행부터 확인하되, `일반검수` 행도 검수 대상입니다. 대화 ID로 필터링한 뒤 발화 번호순으로 전체 대화를 읽습니다. 대화 요약은 합성 시나리오 설정이며 실제 사칭 사실을 독립 증명하는 자료는 아닙니다.
4. 결과는 `미승인`, `승인`, `수정요청`, `보류` 중 하나로 기록합니다. `승인`은 현재 정본의 해당 발화·피싱 여부·라벨·근거를 그대로 승인한다는 뜻입니다. 검수한 행에는 일시를 기록합니다(예: `2026-11-05 14:00 KST`). 수정요청·보류에는 구체적 이유를 반드시 남깁니다. 수정 의견은 `수정할 필드 / 제안값 / 근거`로 적습니다. 피싱 여부는 true/false, 위험 유형은 허용 라벨의 JSON 배열로 제안합니다.
5. 두 사람이 다른 판단을 내렸거나 한 사람이라도 수정요청·보류이면 최종 승인하지 않습니다. 논의한 결론과 수정안은 `합의_수정안`에 기록합니다. 수정이 필요하면 별도 후보본에서 수정 및 재검수를 진행해야 하며, 이 CSV의 원본 열이나 기존 정본 JSONL을 직접 수정하지 않습니다.
6. 두 사람이 모두 현재 내용에 승인했고 미해결 의견이 없을 때만 `최종_합의_결과=승인`과 `최종_합의_일시`를 기록합니다. 최종 승인은 행마다 기록하며 136행이 모두 완료돼야 전체 검수가 완료됩니다. 수정안이 남아 있는 경우 현재 원본의 승인과 혼동하지 말고 별도 후보본의 검수로 이어갑니다.
7. 아래 검증 명령을 실행해 136개 ID의 누락·중복, 원본 열 변경, 결과값, 검수 일시, 두 사람 승인 여부를 확인합니다. **검증 PASS는 사람 승인이나 학습 반영을 뜻하지 않습니다.**

## 열 작성 기준

- 원본 및 안내 열: 대화_ID, 발화_ID, 발화_번호, 화자, 대화_요약, 발화_내용, 피싱_여부, 위험_유형, 라벨_근거, 검토_필요, 검토_사유, 검수자_1·2. 변경하지 않습니다. `위험_유형=[]`는 위험 라벨이 없다는 뜻입니다.
- 사람 입력 열: 검수자별 결과·수정 의견·일시, 최종 합의 결과·수정안·일시.
- `학습_반영=미반영`은 이번 준비 작업의 고정 상태입니다. 모든 사람 승인이 끝나도 이 CSV나 검증 스크립트가 자동으로 학습 데이터에 반영하지 않습니다. 후속 반영은 별도 작업으로 진행해야 합니다.

라벨 판단 기준은 `dataset/label_guide_v3.2.md`입니다. `is_phishing`은 전체 문맥을 보고, 위험 유형은 현재 발화가 직접 수행·표현하는 행위를 기준으로 검수합니다. 이전 발화의 위험 라벨을 자동 상속하지 않습니다.
