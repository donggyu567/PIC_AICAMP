# 작업용 검수 결과 입력 안내

입력 파일은 `human_review_working.csv`입니다. 원본 `human_review.csv`는 보존합니다. 작업용 파일은 16대화·136발화를 대화 ID와 발화 번호의 숫자순으로 정렬했으며, 원본과 같은 열 구조를 사용합니다.

## 결과 입력

아직 결과를 입력하지 않은 행은 **미승인**으로 그대로 둡니다. 내용을 읽었다는 사실만으로 승인으로 바꾸지 않습니다. 검수자가 직접 판단한 행에만 다음 값을 입력합니다.

| 입력값 | 의미 | 함께 작성할 내용 |
|---|---|---|
| 승인 | 현재 발화 내용·피싱 여부·위험 유형·근거를 그대로 승인 | 실제 검수 일시 |
| 수정요청 | 변경이 필요함 | 수정할 필드·제안값·근거와 실제 검수 일시 |
| 보류 | 판단을 확정하기 어려움 | 보류 이유·확인할 사항과 실제 검수 일시 |

검수 일시는 사람이 실제 일시를 입력합니다. 자동으로 채워진 일시는 없습니다.

| 검수자 | 본인이 입력할 열 |
|---|---|
| 김해린 | 검수_결과_김해린, 수정_의견_김해린, 검수_일시_김해린 |
| 임정윤 | 검수_결과_임정윤, 수정_의견_임정윤, 검수_일시_임정윤 |

각자는 자신의 열만 독립적으로 작성합니다. 같은 로컬 CSV를 동시에 저장하지 말고 순차 작성하거나 각자 사본에서 작성한 뒤 발화_ID로 본인 입력 열만 병합합니다. 상대방의 결과를 본인 판단 대신 복사하지 않습니다.

## 빠르게 기록하는 순서

1. Excel에서 CSV UTF-8로 열고 첫 행 필터·헤더 고정을 설정합니다. `대화_ID`로 한 대화씩 필터링하여 `발화_번호` 숫자순으로 확인합니다.
2. `검토_필요=예`인 **29행**은 기존 검토 사유를 읽고 기록합니다. `일반검수`인 나머지 107행도 각자 결과를 입력합니다. CSV에는 색상이나 드롭다운이 저장되지 않으므로 이 열과 `검토_사유`로 구분합니다.
3. 이미 읽어 확인한 내용은 본인 판단에 따라 결과를 기록하고 실제 검수 일시를 입력합니다. 아직 판단을 기록하지 못한 행은 미승인을 유지합니다. 대량 붙여넣기는 본인이 실제로 같은 결론을 내린 행에만 수행합니다.
4. 발화 내용, 피싱 여부, 위험 유형, 라벨 근거, 검토 사유 등 원본 열은 직접 수정하지 않습니다. 변경 제안은 자신의 `수정_의견`에 기록합니다.
5. 두 사람의 독립 입력이 끝나면 불일치·수정요청·보류를 함께 확인합니다. 두 사람 모두 현재 내용을 승인하고 미해결 의견이 없는 행에만 사람이 최종 합의 결과와 실제 합의 일시를 기록합니다. 그 전에는 `최종_합의_결과=미승인`을 유지합니다.
6. 저장할 때 **CSV UTF-8**을 선택합니다. 정렬할 때는 행의 일부 열만 움직이지 말고 표 전체를 함께 정렬합니다. 행·열 이름 및 발화_ID를 변경하지 않습니다.

`학습_반영`은 계속 **미반영**으로 둡니다. 이번 작업은 입력 준비만 수행하며, 기존 승인 JSONL은 변경하지 않습니다. 입력이 끝난 후 작업용 CSV 경로를 지정해 별도로 집계·검증해야 합니다. 기존 검수 규칙의 상세 내용은 같은 폴더의 `README.md`를 따릅니다.
